# OpenLife 前端体验重构计划

> 当前目标：把 OpenLife 从“功能控制台”推进到“用户可理解、愿意每天打开的成长驾驶舱”。

## 核心判断

OpenLife 当前的主要前端问题不是功能缺失，而是用户旅程没有被产品化。页面已经覆盖 Chat、Builder、Dashboard、LifeModel、Memory、Settings、MCP/A2A 等能力，但普通用户打开后仍然会遇到三个问题：

1. 不知道第一步该做什么。
2. 不知道系统现在是否真的理解自己。
3. 不知道每个页面之间有什么关系。

因此下一阶段前端开发不应继续平铺功能，而应围绕“今日行动、构建自我、对话陪跑、记忆与模型安全”重新组织体验。

## 体验原则

- **从模块到旅程**：导航和页面文案优先使用用户语言，而不是技术模块语言。
- **从展示到推动**：Dashboard 不只是展示数据，还要告诉用户下一步最值得做什么。
- **从表单到叙事**：LifeModel 和 Builder 要让用户感觉是在整理人生地图，而不是维护配置表。
- **从黑盒到可信**：AI 的建议、模型写入、工具调用和校准都要说明来源、影响和可拒绝路径。
- **从报错到修复**：所有关键错误都要附带明确修复动作。

## Phase UX-1：试用路径重组

目标：新用户打开应用后，可以不靠开发者解释，完成 Settings → Builder → Chat → Dashboard 的第一条闭环。

开发内容：

- 主导航改成旅程语言：今日、构建我、对话、人生地图、记忆、安全、设置。
- Dashboard 增加“今日驾驶舱”：一句状态判断、三个关键指标、三个下一步行动。
- Builder 首页重做为三种构建方式的产品选择卡：快速构建、渐进构建、苏格拉底构建。
- Chat 增加场景化开场入口：今日规划、情绪复盘、目标拆解、决策陪跑。
- Settings 试用就绪检查从状态文本升级为 checklist，每项有修复按钮。

验收标准：

- 空白用户能明确看到“先构建人生模型”。
- 配置不完整时能明确跳转 Settings。
- Chat 空状态不再只靠用户自己输入第一句话。
- Builder 三种构建方式的区别一眼可懂。

## Phase UX-2：Builder 核心体验产品化

目标：人生模型构建成为 OpenLife 最核心、最可信的首体验。

开发内容：

- 快速构建：定位为 5-10 分钟的可用模型生成。
- 渐进构建：每次只补一个维度，结束后返回维度选择并显示完成度变化。
- 苏格拉底构建：强化“我为什么这样理解你”的解释，不急于写入。
- Review 页面升级为“OpenLife 准备这样理解你”，突出确定项、不确定项、高风险项。
- 应用结果展示 applied、merged、skipped、edited、rejected 的用户化总结。

验收标准：

- 用户能理解每条写入建议的来源和影响。
- 编辑复杂字段不会丢失结构。
- 低风险字段可默认勾选，高风险字段必须主动确认。

## Phase UX-3：人生地图与长期理解

目标：LifeModelEditor 从表单编辑器升级为“OpenLife 眼中的我”。

开发内容：

- 增加默认阅读模式：四维摘要卡片、关键价值观、当前目标、能力资产、状态节奏。
- 表单编辑成为二级入口，不默认压给用户。
- 每个维度展示“当前完整度”和“建议补充项”。
- 版本历史和模型变化结合展示，用户能看到 OpenLife 如何逐渐理解自己。

验收标准：

- 用户不用看 YAML/大表单也能理解自己的人生模型。
- 所有高风险模型改动都有快照和回滚入口。

## Phase UX-4：Chat 陪跑现场

目标：Chat 不只是聊天框，而是把对话转化为行动和模型更新的现场。

开发内容：

- 增加对话模式：今日规划、情绪复盘、目标拆解、决策陪跑、自由聊天。
- Hermes Trace 用户化：说明参考了哪些记忆、选择了哪个模型、有没有调用工具。
- 对话后行动建议：保存为目标、记录状态、更新模型、创建校准建议。
- 错误后支持重试、保留输入、跳转修复。

验收标准：

- 用户知道可以用 Chat 做什么。
- 对话能够自然转化为目标、状态、记忆或模型建议。

## Phase UX-5：视觉语言统一

目标：形成温暖、安静、有秩序的“个人操作系统”气质。

开发内容：

- 定义 CSS 变量：背景、卡片、主色、警告、成功、边框、阴影。
- 替换默认灰白后台感，采用暖灰、墨绿、琥珀、米白的视觉系统。
- 统一卡片、按钮、状态 badge、页面标题。
- 增加轻量动效：页面进入、下一步行动卡 hover、状态呼吸感。

验收标准：

- 页面不再像开发控制台。
- 各页面视觉语言统一，但不同场景仍有主次节奏。

## 已完成进展

- UX-1 第一批已完成：导航旅程化、Dashboard 今日驾驶舱、Builder 三模式入口、Chat 场景化开场、Settings 试用 checklist。
- UX-3 第一批已完成：LifeModelEditor 默认进入“人生地图”阅读模式，表单编辑降为二级入口。

## 下一轮执行范围：UX-4 Chat 陪跑现场

目标：让 Chat 不再只是输入框，而是成为用户每天打开后可以被陪跑、被解释、被转化行动的核心现场。

### 1. Chat 右侧陪跑面板

开发内容：

- 展示当前人生模型脉搏：用户身份、使命/哲学、当前重心、首要目标、核心价值观。
- 展示对话模式卡：今日规划、情绪复盘、目标拆解、决策陪跑、自由聊天。
- 点击模式后直接填入高质量 prompt，而不是只显示说明。
- 当人生模型为空时，面板明确引导去 Builder。

验收标准：

- 用户进入 Chat 后不用思考“我能问什么”。
- 用户能看到 OpenLife 当前依据哪些人生模型信息陪跑。

### 2. Hermes Trace 用户化

开发内容：

- 标题从“技术思考过程”调整为“为什么这样回答”。
- 折叠状态展示用户可读摘要：价值观、目标、工具、耗时、警告。
- 展开后仍保留 Meaning / Strategy / Execution 详情，但降低内部调试感。
- 有工具调用或仲裁 warning 时，用用户语言提示风险。

验收标准：

- 用户能理解 AI 回答依据，而不是看到一段开发调试 JSON。
- 高风险或不确定性不会被隐藏。

### 3. 对话后行动转化

开发内容：

- 对 assistant 回复增加轻量 follow-up 操作：
  - 继续追问
  - 提炼为今日行动
  - 记录当前状态
  - 拆成目标
- 现阶段先通过填入 prompt 实现，不新增后端命令。

验收标准：

- 一次对话可以自然推进到下一步，而不是停在“回答完了”。

### 4. Chat 视觉收口

开发内容：

- 聊天背景、消息气泡、输入区统一到暖色视觉系统。
- 保持现有测试兼容，避免大范围改动交互结构。

验收标准：

- Chat 视觉上与 Dashboard / LifeMap 保持同一产品气质。

## 当前执行范围

本轮执行 UX-4 的第一批：

- Chat 右侧陪跑面板。
- Hermes Trace 用户化摘要。
- Assistant 回复后的行动转化按钮。
- 补充前端测试，确保模式 prompt 和 LifeModel 脉搏可见。
